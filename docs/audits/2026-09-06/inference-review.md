## Findings

### F1 — The configured embedding credential is dead configuration

**Evidence.** `SagaSettings` defines and exports a separate `EMBEDDING_API_KEY` ([`config/settings.py:179-188`](../../../config/settings.py#L179-L188), [`config/__init__.py:53-58`](../../../config/__init__.py#L53-L58)). Repository source references for that field end there. `EmbeddingHTTPClient.get_embedding()` sends no headers at all, while the completion client attaches only `OPENAI_API_KEY` to the completion route ([`core/http_client_service.py:179-185`](../../../core/http_client_service.py#L179-L185), [`232-239`](../../../core/http_client_service.py#L232-L239)).

**Activation and impact.** An embedding endpoint requiring authentication cannot be used even when the dedicated credential is configured. The completion credential is not presently sent to the embedding endpoint, which is the correct isolation direction, but the dedicated routing unit is incomplete.

**Smallest repair.** Define the embedding endpoint authentication contract explicitly (for example, a Bearer header when the dedicated key is non-empty) in `EmbeddingHTTPClient`; do not add any fallback to `OPENAI_API_KEY`.

**Repair tests.** Add transport-level cases with both credentials populated: (1) embedding request contains only the dedicated credential; (2) an empty dedicated key produces no authorization header even if the completion credential exists; and (3) completion still contains only the completion credential. Existing HTTP tests assert the completion header and embedding URL/payload but do not exercise embedding headers ([`tests/test_http_client_service.py:190-208`](../../../tests/test_http_client_service.py#L190-L208), [`214-246`](../../../tests/test_http_client_service.py#L214-L246)).

### F2 — Import-created LLM client has an unowned lifetime on the parser path

**Evidence.** Importing the LLM interface immediately executes `create_llm_service()`, which constructs an `httpx.AsyncClient` ([`core/llm_interface_refactored.py:887-901`](../../../core/llm_interface_refactored.py#L887-L901); transport construction at [`core/http_client_service.py:27-34`](../../../core/http_client_service.py#L27-L34)). `close_llm_service()` is only defined at [`904-906`](../../../core/llm_interface_refactored.py#L904-L906); no production caller was found. `ParserRunner` imports parsers at module load ([`core/parser_runner.py:18-24`](../../../core/parser_runner.py#L18-L24)), invokes their `llm_service` calls, but its `finally` closes only Neo4j ([`233-249`](../../../core/parser_runner.py#L233-L249)). In contrast, bootstrap and orchestration use `async_llm_context()`.

**Activation and impact.** Any parser-runner invocation that makes an LLM request owns no deterministic close of its module-global HTTP client. Repeated invocations in one interpreter can retain pools/sockets and the global service also outlives configuration reloads.

**Smallest repair.** Pick one construction policy: preferably inject an owned LLM service through parser/orchestrator boundaries and remove the production global; alternatively wrap `run_parser_command()` in an LLM context and explicitly bind parser consumers to it. Keep a single close owner and make it idempotent.

**Repair tests.** Use a fake `httpx.AsyncClient`/service and assert exactly one `aclose()` after parser command success and parser failure. Add a direct-import guard proving that an import does not allocate a client, or a test that the application shutdown hook closes the only global exactly once. The present parser-runner tests replace parser classes and do not cover any LLM lifecycle ([`tests/test_parser_runner.py:43-175`](../../../tests/test_parser_runner.py#L43-L175)).

### F3 — Novel input and model output are written into operational logs at the HTTP/parse boundary

**Evidence.** The embedding client logs the first 80 characters of every submitted embedding text ([`core/http_client_service.py:179-182`](../../../core/http_client_service.py#L179-L182)). Invalid embedding input logs `repr(text)` ([`core/llm_interface_refactored.py:151-154`](../../../core/llm_interface_refactored.py#L151-L154)). HTTP status handling logs the first 200 response characters ([`core/http_client_service.py:99-104`](../../../core/http_client_service.py#L99-L104)); completion content extraction logs the full invalid response object ([`core/llm_interface_refactored.py:545-573`](../../../core/llm_interface_refactored.py#L545-L573)). This conflicts with the interface-level stated intent to avoid logging raw prompt content on completion failures ([`core/llm_interface_refactored.py:10-13`](../../../core/llm_interface_refactored.py#L10-L13)).

**Activation and impact.** Scene, outline, and entity text can be persisted to console/file logs in normal embedding calls or malformed-provider/error paths. Provider errors may also echo request content. This violates the local prompt-content boundary independently of credential values.

**Smallest repair.** Replace raw request/response logging at these points with length, content hash, status, and bounded structured provider-error metadata that excludes body text. Retain an explicit diagnostic opt-in only if it is safe for this single-user product.

**Repair tests.** Capture structured logs while submitting a unique canary string and malformed/error response body; assert the canary is absent and hash/length are present for embedding, status-error, and malformed-completion branches.

### F4 — Embedding cache identity and API validation are insufficient for configurable models/endpoints

**Evidence.** The cache key is only `md5(text.strip())` ([`core/llm_interface_refactored.py:131-162`](../../../core/llm_interface_refactored.py#L131-L162)); it excludes model, endpoint, configured dimension, dtype, and config generation. The validator accepts the primary `embedding` field if it is merely a list, flattens nested values, checks only resulting shape, and never calls `np.isfinite()` ([`220-258`](../../../core/llm_interface_refactored.py#L220-L258)). The fallback accepts any top-level numeric list as an embedding ([`229-239`](../../../core/llm_interface_refactored.py#L229-L239)). Cached output is later copied into entity Cypher statements without an independent numeric/shape gate ([`core/entity_embedding_service.py:202-255`](../../../core/entity_embedding_service.py#L202-L255)).

**Activation and impact.** After a model/endpoint/config reload, a same-text lookup can return a prior model's vector and label it with the new model on persistence. `NaN`/infinite values, a nested one-row vector, or a same-dimension unrelated numeric response field can reach cache/storage. These are configuration-sensitive semantic errors, not just provider failures.

**Smallest repair.** Build cache identity from normalized text plus the effective embedding model, endpoint, dimension, dtype, and a monotonic configuration generation (or clear the namespace on a relevant reload). Accept only the documented response field and an exactly one-dimensional row of the configured length; convert to target dtype and reject non-finite values before caching or persistence. Revalidate at the persistence boundary if it remains public.

**Repair tests.** (1) Same text with model/endpoint A then B makes two backend calls and returns B's vector. (2) Correct-length vectors containing `NaN` or either infinity return no vector and leave no cache entry/Cypher statement. (3) Reject a nested `[1, dim]` response and an unrelated numeric top-level field. (4) Verify entity persistence rejects malformed direct service output even when bypassing `EmbeddingService`. Current focused tests cover truncation, empty text, dimension match, and fallback acceptance, but not finiteness, cache configuration identity, or persistence revalidation ([`tests/test_llm_interface_content_extraction.py:133-155`](../../../tests/test_llm_interface_content_extraction.py#L133-L155), [`158-252`](../../../tests/test_llm_interface_content_extraction.py#L158-L252); [`tests/test_entity_embedding_service.py:92-149`](../../../tests/test_entity_embedding_service.py#L92-L149)).

### F5 — Runtime configuration reload is split-brain and can override process-supplied credentials

**Evidence.** Startup dotenv loading does not override the process, but `reload_settings()` uses `load_dotenv(override=True)` ([`config/settings.py:15-18`](../../../config/settings.py#L15-L18), [`config/loader.py:62-73`](../../../config/loader.py#L62-L73)). It rebinds `config.settings` and its field names only ([`75-88`](../../../config/loader.py#L75-L88)); `config.reload()` discards its success/failure return ([`config/__init__.py:172-185`](../../../config/__init__.py#L172-L185)). `config.validator` captured the old singleton in `current_settings` at import time ([`config/validator.py:28-30`](../../../config/validator.py#L28-L30)). `Temperatures` also captures values as class attributes ([`config/settings.py:400-409`](../../../config/settings.py#L400-L409)), while completion reads `config.Temperatures.OVERRIDE` ([`core/llm_interface_refactored.py:355-360`](../../../core/llm_interface_refactored.py#L355-L360)).

**Activation and impact.** After reload, validation and temperature override can read pre-reload objects while the legacy module fields read newly rebound values. Reload also permits a local `.env` to replace externally supplied endpoint/credential values, contrary to the import-time precedence policy. The current test explicitly accepts either old or changed value, so it does not establish a reload contract ([`tests/test_configuration.py:29-51`](../../../tests/test_configuration.py#L29-L51)).

**Smallest repair.** Make runtime reload either unsupported after startup or transactional and explicit: retain process-over-file precedence unless an explicit trusted operator option says otherwise; have consumers resolve the current singleton at call time (or replace all dependent derived objects atomically); return/raise an unambiguous reload result. Do not reconfigure global logging handlers on every settings-module reload.

**Repair tests.** With a temporary dotenv fixture and no real secrets: (1) assert process endpoint/key wins after default reload; (2) assert reload failure is observable; (3) change temperature override and a cross-field value, reload, then prove both `validate_all()` and a completion payload see the new values; (4) assert one root handler after repeated reloads.

### F6 — Retry controls can silently disagree with call sites and are not validated as runnable configuration

**Evidence.** `LLM_RETRY_ATTEMPTS`, `JSON_PARSE_RETRY_ATTEMPTS`, `MAX_CONCURRENT_LLM_CALLS`, and delay/timeout fields have unconstrained primitive definitions ([`config/settings.py:246-256`](../../../config/settings.py#L246-L256)). A transport retry count of zero skips the loop and raises the generic no-specific-error exception ([`core/http_client_service.py:80-86`](../../../core/http_client_service.py#L80-L86), [`129-136`](../../../core/http_client_service.py#L129-L136)); zero concurrency creates a semaphore that no call can acquire ([`33-34`](../../../core/http_client_service.py#L33-L34)). Several parser retries use the configurable range but hard-code terminal behavior at attempt `2`, such as global world-item extraction ([`core/parsers/global_outline_parser.py:254-270`](../../../core/parsers/global_outline_parser.py#L254-L270)) and event-item extraction ([`core/parsers/act_outline_parser.py:668-700`](../../../core/parsers/act_outline_parser.py#L668-L700)). The JSON service itself correctly rejects a count below one ([`core/llm_interface_refactored.py:706-707`](../../../core/llm_interface_refactored.py#L706-L707)), producing an inconsistent boundary.

**Activation and impact.** Non-default retry configuration can hang (zero concurrency), give an opaque generic exception (zero transport retries), or stop parser retry after attempt two even when configured for more. Transport retries and JSON/parser retries also stack, so the actual provider request ceiling is not represented by a single configuration value.

**Smallest repair.** Put `ge=1` constraints on attempt/concurrency fields and positive constraints on delay/timeout; replace all hard-coded terminal attempt comparisons with the effective configured value. Decide whether JSON-repair attempts should reuse transport budget or document/implement their composed maximum.

**Repair tests.** Parameterize settings construction/validation for `0`, negative, and valid boundaries; use a fake transport for 1/2/3 parser parse failures to assert exactly the configured attempts; assert the composed request ceiling and that a `429` obeys the intended backoff policy. Existing HTTP tests cover default-like 2/3 retries only ([`tests/test_http_client_service.py:60-137`](../../../tests/test_http_client_service.py#L60-L137)).

### F7 — The same textual prompt contract is parsed differently across call paths

**Evidence.** `extract_world_items_lines.j2` mandates a JSON array and exactly three keys per item ([`prompts/knowledge_agent/extract_world_items_lines.j2:32-37`](../../../prompts/knowledge_agent/extract_world_items_lines.j2#L32-L37)). The initialization route enforces exact keys and scalar validity ([`core/langgraph/initialization/commit_init_node.py:471-539`](../../../core/langgraph/initialization/commit_init_node.py#L471-L539)); `GlobalOutlineParser` uses the same template but accepts extra keys and skips missing/invalid entries ([`core/parsers/global_outline_parser.py:274-339`](../../../core/parsers/global_outline_parser.py#L274-L339)); `ActOutlineParser` merely filters for the presence of three keys ([`core/parsers/act_outline_parser.py:487-510`](../../../core/parsers/act_outline_parser.py#L487-L510)).

For scene extraction, templates describe exact wrappers and member fields (for example character updates at [`prompts/knowledge_agent/extract_characters.j2:24-53`](../../../prompts/knowledge_agent/extract_characters.j2#L24-L53) and world updates at [`extract_locations.j2:8-37`](../../../prompts/knowledge_agent/extract_locations.j2#L8-L37)). The shared parsers only select expected wrapper values and filter dictionary members ([`core/langgraph/nodes/scene_extraction_parsing.py:17-112`](../../../core/langgraph/nodes/scene_extraction_parsing.py#L17-L112)); callers then coerce missing/wrong member types with `str`, `list`, and `dict` ([`core/langgraph/nodes/scene_extraction.py:219-230`](../../../core/langgraph/nodes/scene_extraction.py#L219-L230), [`323-336`](../../../core/langgraph/nodes/scene_extraction.py#L323-L336)). Generic JSON salvage accepts embedded JSON even when prompts forbid any surrounding content ([`utils/common.py:148-189`](../../../utils/common.py#L148-L189)).

**Activation and impact.** A response with an extra/missing/wrongly typed field has path-dependent semantics: one path rejects, another silently publishes partial data, and another produces no extracted entities. Operators cannot tell contract violation from a legitimate empty extraction, and tests do not cover the shared scene parsers (source search found no direct focused test references).

**Smallest repair.** Define versioned Pydantic/schema contracts next to each template family, then make every consumer of a template call the same parser. Choose and document one policy per workflow class: strict fail before persistence for canonical initialization, or an explicitly reported item-level rejection ledger for best-effort extraction. Keep salvage as a separately named compatibility mode, not the default for a `JSON only` contract.

**Repair tests.** For each template family, render a minimal valid fixture and feed it through every consumer that uses it; assert identical acceptance/normalization. Add negative cases for extra wrapper/item keys, absent wrappers, nested members, wrong scalar/list types, code fences, and trailing commentary. Assert that a best-effort path records rejected rows rather than returning an indistinguishable empty list.
